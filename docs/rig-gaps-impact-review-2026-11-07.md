### Pushback and proposed changes to the requested designs

1. **Do not prefix every canonical session name with provider and project.** C14 can show those as separate searchable columns and avoid duplicate/stale names after a project rename or provider transition. Native UI `/rename` is an optional display alias; the Rig record remains an exact anchor with independent provider/project metadata.
2. **Do not auto-reap on SessionStart or `/wrap` solely from PID age.** C07 should default to read-only suspected-stale classification and a dry-run, then an explicit reversible archive. VS Code shares a process across conversations and provider sessions can resume after the owning PID exits; a wrap obligation must be preserved.
3. **Do not auto-mirror an arbitrary provider file edit.** C10 should regenerate from a declared canonical source or present a semantic transform and diff. Claude `/command` syntax, Codex `$skill` syntax, user-owned overrides and provider-only content make blind copying unsafe. A post-write audit can detect drift; an approved targeted fix can resolve it.
4. **Do not scan every file in `/private/tmp` by mtime.** C17 should use explicit helper registration at creation; mtime cannot prove session ownership and may scoop up cookies, auth, or data dumps. The wrap report can remind the agent of registered-but-unreviewed helpers.
5. **Do not promise a full-context scanner across compactions.** C16 can inspect available transcript/checkpoint material and record what is missing. A prompt at the point of discovery plus promotion from `ERRORS.md`/`RIG_GAPS.md` is more reliable than attempting to reconstruct inaccessible context later.
